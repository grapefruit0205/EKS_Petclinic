# EKS Project — ALB · WAF 기반 3-Tier 설계 및 구축

사용자 제공 PDF, Notion 학습자료, 지정 Petclinic 저장소를 대조한 **설계 문서(v2)** 와, 그 설계를 **실제 AWS 계정에 Terraform으로 구축·전환한 결과**를 함께 담고 있습니다.

> **v2 전환 완료 (2026-10-22)**
> API Gateway HTTP API · VPC Link V2 · internal ALB · Cognito를 **제거**하고 **internet-facing ALB + AWS WAF** 직접 진입으로 전환했으며, **실제 AWS에 적용·검증까지 마쳤습니다.**
> VPC는 4계층 → **3계층**(public / private workloads / isolated data)으로 축소했습니다. v1 이력은 [구축 결과](구축_결과.md) 1장 이하에 보존했습니다.

## 기본 아키텍처 (v2)

```text
Browser → Route 53 / ACM → internet-facing ALB (WAF 연결)
        → Nginx Web (EKS) → Spring MVC/Tomcat App (EKS) → RDS MySQL
```

- 원본 JSP/MVC 화면과 폼 유지. Spring Boot·전체 REST API·MSA로 가정하지 않습니다.
- Managed Node Groups + AWS Load Balancer Controller 사용. ingress-nginx는 신규 도입하지 않습니다.
- ALB는 **public 서브넷**, EKS 노드·Pod는 private workloads, RDS는 isolated data 서브넷에 둡니다.
- App 인증·인가·CSRF, 공유 세션, 전용 health, DB migration은 **추가 구현 대상**입니다.
  v2에서는 Cognito 대신 **Spring Security 폼 로그인 + DB 계정 + Spring Session JDBC**를 사용합니다.
- Terraform은 기반 인프라와 WAF를, LBC는 ALB를, Helm/Argo CD는 워크로드를 관리합니다.
- 비밀값은 빌드·Git·문서에 넣지 않고 런타임 파일로 주입합니다.

## Phase 안내

각 Phase의 상세 작업·산출물·완료 조건·실패 대응은 설계안 8장에 있습니다.

| Phase | 목표 |
|---|---|
| 0 | 요구사항·예산·버전·ADR 확정 |
| 1 | 원본 WAR/JSP·런타임 적합성 검증 |
| 2 | 앱 운영화·보안·프로브·로컬 3-Tier |
| 3 | AWS 기반망(3계층 VPC)·IAM·ECR·예산 |
| 4 | RDS·Secrets·마이그레이션·백업 |
| 5 | EKS 플랫폼·addon·접근 제어 |
| 6 | Web/App·DB 연결 및 인터넷-facing ALB |
| 7 | WAF·TLS·도메인·안전한 공개 |
| 8 | CI/CD·릴리스·롤백 자동화 |
| 9 | 확장·관측·비용 튜닝 |
| 10 | 장애·복구·인수·자원 정리 |

예상 순차 작업량은 **15~24작업일**입니다. P4/P5는 병행할 수 있으며, 기간·용량·성능·RPO/RTO는 측정값이 아닌 초기 제안입니다.

## v1 → v2 전환 (적용 완료)

| 항목 | v1 (구축 이력) | v2 (현재 배포 · 실측 완료) |
|---|---|---|
| 외부 진입점 | API Gateway HTTP API + VPC Link V2 | **internet-facing ALB** |
| 보호 계층 | 없음 (HTTP API는 WAF 직접 연결 불가) | **AWS WAF Regional WebACL** (Common·SQLi·KnownBadInputs + IP rate) |
| ALB | `scheme=internal`, private ingress 서브넷 | **`scheme=internet-facing`, public 서브넷** |
| 서브넷 계층 | 4계층 (public / ingress / workloads / data) | **3계층** (public / workloads / data) |
| 인증 | Cognito User Pool 생성됨, **앱 코드 미구현** | Cognito **제거** → 폼 로그인 + DB 계정 + Spring Session JDBC (**설계만, 미구현**) |
| ECR | 사용 중 | **유지** (immutable tag·scan·lifecycle·KMS) |
| 도메인 | `qgby7mqw7l.execute-api...` (커스텀 도메인 미적용) | `https://clinic.mission-critical.site` (Route 53 A → ALB, ACM ISSUED) |
| 요청 타임아웃 | 30초 제한(API Gateway) | ALB idle timeout 기준으로 완화 |

## 구축·검증 현황

- 자료 대조와 설계 문서화는 완료했습니다. Notion 알려진 본문 **185개**를 단일 조회로 **본문확인 185개(부분확인 0, 조회기록 0, 잔여 0)** 까지 마쳤습니다.
- **v1 AWS 구축 완료**: API Gateway → VPC Link V2 → internal ALB → Nginx Web → Tomcat App → RDS MySQL 전 구간이 실제로 **HTTP 200** 으로 동작했습니다(`/`, `/vets.json`, `/vets.xml`, `/owners/find`, 정적 CSS).
- **v2 전환 완료 (2026-10-22)**: API Gateway·VPC Link·internal ALB·Cognito를 제거하고 internet-facing ALB + AWS WAF로 컷오버했습니다. `https://clinic.mission-critical.site` **HTTPS 200**, HTTP→HTTPS **301**, TLS 인증서 정상, ALB 타깃 **2/2 healthy**, WAF 연결 확인.
- **WAF 차단 검증 완료**: SQLi·XSS·Log4Shell 페이로드 **403**, 정상 요청 **200**. CloudWatch `aws-waf-logs-petclinic-dev` 에 BLOCK 이벤트가 기록되는 것까지 확인했습니다.
- **v2 기준 미완료(성공으로 표시하지 않음)**: 앱 폼 로그인 인증 코드, 앱 전용 `/health` 엔드포인트, NetworkPolicy, HPA/Cluster Autoscaler, migration Job, 부하·장애·복구 시험, WAF 오탐 관측.
- 실제 개인정보나 원문 예시 자격증명은 사용하지 않았습니다. Terraform state 에 DB 평문 비밀번호가 없음을 확인했습니다.

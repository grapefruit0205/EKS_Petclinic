### 그대로 복사하지 않은 항목

1. **소스 차이:** PDF의 backend/frontend는 `cloud-sue` 포크/별도 Web 저장소다. 사용자가 지정한 upstream `spring-framework-petclinic`과 설정 키·런타임·프런트 구성이 다르다.
2. **비밀 노출:** Maven build 인자·Compose·Secret 예시에 인증정보가 포함되어 있다. 원문 값을 결과물에 복제하지 않고 Secret 외부 주입으로 대체했다.
3. **장기 키:** Bastion의 `aws configure` 장기 액세스 키 패턴 대신 SSO/역할/SSM/OIDC를 채택했다.
4. **관리 화면:** Tomcat manager/host-manager의 접근 제한 해제를 사용하지 않는다. 운영 이미지에서 관리 앱을 제거한다.
5. **버전:** Java 17/Tomcat 9 예시를 현재 Spring 7/Servlet 6.1 원본에 적용하지 않는다. JDK 21/Tomcat 11 후보를 검증한다.
6. **컨트롤러:** ingress-nginx와 Nginx Web 서버는 별개다. 종료된 ingress-nginx를 신규 도입하지 않고 LBC를 사용한다.
7. **비용:** ECR 무료 500MB 등의 문구를 일반 요금 보장으로 해석하지 않는다. EKS/NAT/ALB/로그/endpoint/IPv4 등 전체 비용을 계산한다.
8. **구현 형태:** PDF의 `docker commit` 시행착오를 반복하지 않고 Git 관리 Dockerfile·불변 digest·CI 검증을 기본으로 둔다.

### 자료의 제한과 교정 원칙

- **코드 누락:** Docker 3일 과정 복사본 다수에 `Loading Bash code…`, `Loading Mermaid code…`, `Loading...`가 본문으로 남아 있다. 일부는 태스크 도중 끝나거나 상세 단계를 원문 참조로 돌린다. 이는 실제 명령을 확보했다는 뜻이 아니다. 확인 목록에 이를 명시했다.
- **내용 제한:** 학생용 PetClinic 프로젝트에 제목 수준으로만 제공된 세부 단계가 있다. 없는 상세 설정을 읽었다고 주장하지 않는다.
- **첨부 경계:** 노션 내 SVG/HTML 첨부는 페이지의 설명·캡션을 근거로 삼았으며 모든 첨부를 다운로드·실행하지 않았다. 원문 외부 참고 링크와 연결된 다른 GitHub 저장소 전체도 이번 지정 소스와 구분한다.
- **시점 차이:** 노션 페이지의 마지막 수정일과 fetch 스냅샷 시각은 서로 다르다. 최신 시각만으로 기술적 정확성을 보장하지 않는다.
- **네트워크 설명:** 같은 Docker backend bridge에 Web와 DB가 있으면 Web에서 DB로 갈 수 있다. host port 미공개는 workload 간 격리와 다르다. 로컬안은 네트워크를 재분리하고 EKS는 SG/NetworkPolicy로 음성 검증한다.
- **DNS 일반화:** Nginx upstream이 항상 첫 IP 하나만 쓴다는 설명을 일반 법칙으로 채택하지 않았다. 버전·resolver·DNS 응답·연결 재사용을 검증하고 EKS에서는 Service DNS/EndpointSlice와 readiness를 사용한다.
- **용량/버전 차이:** Flask 200MB, Docker 단일 EC2 비용, Docker 버전별 storage 기본값 등을 Java/EKS 운영의 고정 규격으로 복사하지 않는다.
- **실습 도구의 범위:** kubeadm/Calico/MetalLB 온프레미스 예제와 EKS managed control plane/VPC CNI/LBC를 섞지 않는다. API Gateway와 Kubernetes Gateway API도 별개다.
- **스토리지/보안:** RWO는 Pod가 아니라 노드 단위이며, PV의 실제 내구성은 백엔드에 의존한다. `Retain`은 백업이 아니다. RDS 기본안에는 학습용 MariaDB StatefulSet/PVC를 중복 도입하지 않는다. PSS 기준과 PSA 집행을 구별하고 앱의 non-root 이미지·쓰기 경로와 함께 검증한다.
- **Helm/운영:** `deployed`, dry-run, PVC `Bound`는 애플리케이션 정상 동작의 증거가 아니다. Helm rollback은 DB 데이터/스키마를 복원하지 못한다. Helm values·렌더링 결과·release Secret에도 비밀이 남을 수 있어 외부 Secret 참조를 사용한다. Job/CronJob과 migration은 재실행 가능성을 고려해 멱등성·잠금을 검증한다.
- **요약의 단순화:** 종료 코드 143만으로 종료 신호 처리 실패를 단정하지 않는다. ReplicaSet의 selector와 ownerReferences를 구분하고, EndpointSlice는 프록시 홉이 아니라 endpoint/준비도 정보다. not-ready endpoint가 목록에 남을 수 있으므로 조건도 확인한다. 실제 데이터 전달은 ALB·프록시·Service 구현에 달려 있다.
- **준비도와 수명:** startupProbe도 실패 임계치를 넘으면 재시작을 유발한다. readiness는 의존성 기동 순서를 보장하지 않아 앱의 재시도·유한 대기와 별도로 설계한다. Secret 볼륨 갱신과 앱의 재로딩은 다르며 고정 갱신 시간도 보장하지 않는다. 학습용 호스트 경로/PVC 보존은 백업·노드 독립성의 보장이 아니다.
- **init·프로브의 과도한 일반화:** 실패한 일반 init 컨테이너는 보통 그 단계부터 재시도하며 항상 첫 init부터 재실행되는 것은 아니다. 전체 재실행 가능성에 대비한 멱등성은 필요하고 Job/hook도 정확히 한 번의 실행을 보장하지 않는다. HTTP/TCP probe는 kubelet이 수행하며 readiness 실패는 보통 EndpointSlice의 `ready` 조건을 바꾼다. IP가 반드시 삭제되는 것이 아니고 기존 연결의 drain도 별도다. Boot readiness가 DB를 자동 검사한다고 가정하지 않으며 `mysqladmin ping`만으로 인증·스키마·CRUD 준비를 증명하지 않는다.
- **빌드·진단·Service 예외:** Kubernetes 자체는 이미지 빌드 도구가 아니지만 노드에서 빌드가 기술적으로 불가능한 것은 아니다. 본 설계는 운영 노드 빌드를 금지하고 CI로 분리한다. `nerdctl build`는 BuildKit에 의존하며 `crictl`도 중지·삭제 명령이 있어 조회 전용이라는 설명을 채택하지 않는다. ClusterIP 표현·프록시 규칙·NodePort 접근성은 구현/설정에 따라 다르고, NodePort도 할당·규칙 동기화 실패가 가능하다.
- **유지보수·확장의 보장 한계:** drain은 Pod 자체의 이동이 아니라 축출 후 컨트롤러의 재생성이며 여유 자원·PDB·볼륨·종료 처리가 필요하다. cordon에도 DaemonSet·명시적 노드 지정 등의 예외가 있다. 강제 Pod 삭제나 Node 객체 삭제는 실제 프로세스 종료·EC2 종료의 증거가 아니다. HPA 최소 수량·rollout 완료·QoS 등급을 실제 가용성 보장으로 취급하지 않고 `latest` 설치와 kubelet TLS 검증 생략을 운영 표준에서 제외한다.
- **설정·스토리지·IP 계획:** root 소유 `0400` Secret 파일은 non-root 앱이 읽지 못할 수 있어 UID/GID·CSI 지원 권한을 실제 검증한다. 파일 갱신과 앱 재로딩을 구분하고 비밀 출력은 금지한다. taint는 보안 경계가 아니며 toleration·노드 라벨 변경 권한도 제한한다. RWO는 노드 단위의 동시 사용 제약이지 영구 노드 고정의 의미가 아니다. SC/PVC 생성만으로 provisioning·mount·복원 성공을 보장하지 않는다. Calico 예제의 노드/Pod CIDR 분리·단일 pool 일치 규칙을 기본 Pod IP가 VPC subnet에서 할당되는 EKS VPC CNI에 그대로 복사하지 않는다. Service/HTTPRoute는 설정 참조 관계이며 반드시 순차 데이터 프록시 홉은 아니다.
- **EC2 보충:** Ubuntu/Rocky의 Docker 실습 호스트와 EKS 관리 노드 구성을 구별한다. SSM은 agent·역할 외에도 AWS 서비스로 나가는 통신 경로가 필요하다. EC2 중지로 EBS/EIP/snapshot 등 모든 비용이 없어지는 것이 아니며 원문의 가격·AMI 지원은 구축 시 다시 확인한다.
- **Docker 본문 보충:** 익명 볼륨도 해시 이름으로 다시 연결할 수 있다. 중지된 컨테이너가 참조하는 볼륨과 컨테이너를 삭제한 뒤 남은 미참조 볼륨을 구별한다. 가동 중 DB 파일의 단순 tar 복사는 일관된 백업을 보장하지 않으므로 DB 전용 백업·정지/일관성 확보·복원 시험을 별도로 둔다.
- **접근·진단 경계:** Linux 호스트는 게시하지 않은 컨테이너 포트에도 컨테이너 IP로 직접 접근할 수 있다. 내부 curl 성공만으로 외부 실패 원인을 하나로 단정하지 않는다. SG·호스트 방화벽·바인딩·라우팅을 함께 확인하고, docker-proxy 존재나 실제 client IP 보존도 구현·경로별로 검증한다. exec는 셸 유무·실행 파일·권한에 따라 제한된다.
- **빌드·비밀 관리:** history의 0B 설정 항목과 실제 파일시스템 레이어를 구별한다. 멀티스테이지와 캐시는 각각 배포 이미지와 빌드 과정의 최적화이며, 오류를 숨기는 `|| true`나 테스트 생략을 운영 CI로 복사하지 않는다. Compose의 로컬 secret 파일은 암호화 비밀 저장소가 아니며, `_FILE` 같은 파일 설정도 앱이 지원해야 한다. Petclinic에는 별도 구현이 필요하다.
- **Kubernetes 적용 검증:** 모든 kind에 spec이 있는 것은 아니며 Secret/ConfigMap·볼륨 등의 이름 참조도 존재한다. selector와 소유권을 구분한다. Deployment의 server-side dry-run은 아직 생성되지 않은 하위 Pod의 PSA·Quota, 스케줄링·이미지 기동·기능 시험을 대신하지 못한다. EKS 지원 버전과 addon 호환 조합을 별도로 고정하고 원문의 로컬 최신 버전을 그대로 채택하지 않는다.
- **네트워크·종료 검증:** NetworkPolicy는 허용 규칙의 합집합이고 라벨 수정 권한도 보안 경계다. `실패 || echo BLOCKED`는 DNS·이미지 pull·실행 실패도 차단 성공처럼 보이게 하므로 정상 대조군·종료 코드·관측 근거로 구분한다. Gateway 상태 조건·EndpointSlice 주소 수·health 200만으로 실제 분배나 CRUD 무중단을 증명하지 않는다. preStop 대기는 종료 유예 예산 안에서 실측하며 5초 같은 예시로 drain 완료를 보장하지 않는다.
- **외부 노출 예외:** LoadBalancer는 `allocateLoadBalancerNodePorts: false`와 IP target 등에서 NodePort 없이 구성될 수 있다. 주소도 공인 IP가 아닌 내부 주소·DNS hostname일 수 있다. `externalTrafficPolicy`, CNI의 NAT/정책 집행 순서와 실제 타깃 경로를 확인한다. Kubernetes Gateway API의 표준/확장 기능 지원은 구현별로 달라 GatewayClass 이름만 바꾸면 완전히 이식된다고 가정하지 않는다.
- **ECR 매니페스트 인덱스와 DB 서브넷 격리:** BuildKit/buildx가 생성하는 OCI 이미지 인덱스·플랫폼별 매니페스트·provenance 증명으로 인해 ECR에 untagged 행이 함께 생길 수 있으므로, 단순 "태그 없는 이미지 만료" 수명 주기 규칙으로 활성 태그가 깨지지 않게 한다. 또한 Private-DB 서브넷 라우팅 테이블은 VPC local 경로만 두어 설정 실수 시에도 인터넷 경로가 열리지 않게 하고, Web 프록시는 `$http_host`와 `X-Forwarded-Proto`를 보존해 포워딩 뒤 리다이렉트 포트·스킴 손실을 막는다. AWS VPC에서는 MetalLB L2(ARP)가 동작하지 않으며, 자체 구축 kubeadm on EC2의 `SourceDestCheck` 해제·단일 SG 구성을 EKS 관리형 노드/VPC CNI에 그대로 복사하지 않는다.

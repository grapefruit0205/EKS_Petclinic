### 0.4 컷오버 절차 (실행한 순서)

```bash
# 1) v1 edge 제거 — API Gateway · VPC Link · 커스텀 도메인 · A 레코드
```

### 4.1 커스텀 도메인 — NS 위임 이력과 해결 (2026-10-22)

도메인 `mission-critical.site` 는 등록기관이 **가비아**이고, 현재 NS 가 **이미 삭제된 Route53 존**을 가리키고 있다.

| 확인 항목 | 실측 결과 |
|---|---|
| `.site` TLD 위임 NS | `ns-42.awsdns-05.com`, `ns-931.awsdns-52.net`, `ns-1489.awsdns-58.org`, `ns-1909.awsdns-46.co.uk` |
| 위 권한 서버 응답 | **REFUSED** (v1 시점 — 해당 호스티드 존이 더 이상 존재하지 않음) |
| 재귀 리졸버(8.8.8.8) | **SERVFAIL** (v1 시점) → **해결**: 가비아에서 NS 를 kdt5 존 4개로 교체한 뒤 정상 해석 |
| 기존 존의 레코드 | apex/`www`/`clinic`/`api` 모두 A·CNAME·MX·TXT 없음(사용되지 않는 상태) |
| 이번 스택의 Route53 존 | `Z063520230VU5KSTWNGGW` (kdt5), NS `ns-1089.awsdns-08.org`·`ns-1713.awsdns-22.co.uk`·`ns-390.awsdns-48.com`·`ns-789.awsdns-34.net` |
| ACM 인증서 | `arn:aws:acm:ap-northeast-2:123456789012:certificate/3335292a-8a8c-4da1-a8a6-970167fad9d7` (`clinic.mission-critical.site`) — **ISSUED (2026-10-22)** |
| 검증 CNAME | `_97b135484cbdba1044732f1da544a9cb.clinic.mission-critical.site` → `_ea770cd05ec97dd10e9bdb0cfeb7a402.wzccmgtwzk.acm-validations.aws.` (kdt5 존에 생성·응답 확인) |

**조치 완료 (2026-10-22):** 가비아에서 `mission-critical.site` 의 네임서버를 kdt5 존 NS 4개로 교체했다.
전파 후 ACM 이 자동으로 **ISSUED** 되었고, Route 53 A(alias) 레코드가 ALB 를 가리킨다.
기존 존이 이미 죽어 있어 다른 레코드가 사라진 것은 없다.

교체 이후 실제로 수행한 순서는 **0.4 컷오버 절차**에 있다(v2 기준).

> ACM 인증서는 무료이며 검증 전에는 과금되지 않는다. 검증 대기(`aws_acm_certificate_validation`)는
> `enable_custom_domain` 으로 분리해 두어 NS 위임 전에도 `terraform apply` 가 막히지 않도록 했다.
> v2에서는 커스텀 도메인을 API Gateway 가 아니라 **Route 53 A(alias) → ALB** 로 연결한다(`terraform/dns/`).

## 5. 구축 중 해결한 장애 (재현 방지용)

| 증상 | 원인 | 조치 |
|---|---|---|
| 노드그룹 `NodeCreationFailure` | vpc-cni addon 이 노드그룹 **이후** 생성되어 노드가 `NotReady` | addon 을 클러스터 직후, 노드그룹을 addon 이후로 순서 변경 |

## 7. 비용·정리

- 이 구축은 **실제 과금 리소스**다. EKS control plane, 노드 4대(`m6i.large`), RDS Multi-AZ(`db.m6g.large`), NAT 2개, interface endpoint 9개, **internet-facing ALB + AWS WAF**, CloudWatch Logs, ECR, KMS 가 계속 과금된다.
- `ExpiresAt=2026-11-05` 태그를 모든 리소스에 부여했다. 예산 알림은 `Project=petclinic-3tier` 기준이며 **알림은 자동 상한이 아니다**.
- v1 전용이던 **API Gateway / VPC Link / Cognito 는 이미 삭제**되어 더 이상 과금되지 않는다.

정리 순서(v2):

```bash
# 1) Ingress 삭제 → LBC 가 ALB/TG 를 지울 때까지 확인 (aws elbv2 describe-load-balancers)
kubectl delete -f EKS_Project/k8s/30-ingress.yaml

# 2) dns 스택 — Route 53 A 레코드
cd EKS_Project/terraform/dns && terraform destroy

# 3) foundation — WAF · VPC · EKS · RDS · ECR · KMS · Secrets
cd EKS_Project/terraform && terraform destroy
# 주의: RDS deletion_protection / 최종 스냅샷 정책을 먼저 확인한다
```

> `terraform/edge/` 는 v1 전용이며 **이미 destroy 완료**했다. state 가 비어 있으므로 다시 실행하지 않는다.

## 8. 아직 검증하지 않은 것

아래는 **수행하지 않았으므로 성공으로 표시하지 않는다**.

- 폼 로그인(`ROLE_READER`/`ROLE_WRITER`) → 보호자 등록 → 로그아웃 브라우저 E2E (앱 인증 코드 미구현. Cognito 는 v2에서 폐기)
- 무인증 쓰기 차단 / CSRF / 권한 부족 403
- Web→RDS 직접 접근 차단, 임의 Pod→App/RDS 차단 (NetworkPolicy 미적용)
- HPA scale-out, Cluster Autoscaler 노드 증가
- RDS failover, PITR 복원, RPO/RTO 측정
- Secret rotation 후 재접속
- 부하 테스트(p95, 성공률), p95 ≤1초 목표
